# TLA+ model and the TLC cross-check

The Data Link tables are rendered as a TLA+ module and model-checked with TLC, as a second checker independent of the two-station explorer (`docs/explorer.md`). It is the first step of Phase 2 of packethacking/ax25spec#116: a model generated from the emitted tables, never written by hand, so it cannot drift from the figures, and two tools that must agree on the calibration set.

Run it:

```sh
dotnet run --project codegen/src/Packet.Sdl.CodeGen -- --tla          # regenerate spec/tla/Ax25DataLinkTables.tla
export TLA2TOOLS_JAR=/path/to/tla2tools.jar                            # TLC 2.19 (tlaplus v1.7.4)
dotnet run --project codegen/src/Packet.Sdl.TlaCheck -- --parallel 6   # the calibration suite, explorer vs TLC
dotnet run --project codegen/src/Packet.Sdl.TlaCheck -- --grid --parallel 8   # the explorer's 576-cell grid
dotnet run --project codegen/src/Packet.Sdl.TlaCheck -- --help
```

`TlaCheck` prints one row per scenario and exits 0 only if every row agrees. Each model directory (under `--work`, default `<temp>/ax25sdl-tlacheck`) keeps the rendered tables, the configs and TLC's full output, so any row can be rerun by hand with `java -cp tla2tools.jar tlc2.TLC -config MC_Safety.cfg TwoStation.tla`.

## The pieces

| File | Written by | What it is |
| --- | --- | --- |
| `spec/tla/Ax25DataLinkTables.tla` | generated (`--tla`) | The tables as constant TLA+ data: `Pages[state][event]` is that page's transitions on that event in file order, `Subroutines[name]` its paths. Each has its guard (`Is(atom)` / `Not(atom)` conjuncts), loop regions, action chain (`Box(kind, verb)`) and next state. |
| `spec/tla/Ax25Runner.tla` | hand | How a table is run: guard selection, loop regions, subroutine calls and their bindings, the next state, and the frame around one dispatch. A port of the reference interpreter's `Dispatch`, `ExecuteActions`, `RunLoop` and `InvokeSubroutine` (`Machine.cs`). | `spec/tla/Ax25Meaning.tla` | hand | The default meaning: what each verb, guard atom and signal does. A port of `Machine.cs`, arm by arm. Its own choices are in `docs/tla-meaning-policies.md`, which is withheld from an independent author. |

| `spec/tla/Ax25Values.tla` | hand | The value shapes that cross the interface: events, frames, effects, the error convention, the two maps the harness reads. |

| `spec/tla/Ax25MeaningIndependent.tla` | hand | A second meaning, written from the spec text and the interface alone, with no access to the interpreter or `Ax25Meaning.tla` (ax25spec#116 Phase 2, Step B). | `codegen/src/Packet.Sdl.TlaCheck/fixtures/` | script, documented | Twenty-nine deliberately broken table sets (twenty-four before packet-net/ax25sdl#97's PR B, which added five for the save rules) that fail acknowledgement coherence, quiescence, the release rest, the give-up rule's settled state (with and without T3), the reconnect answer rule, the link report rule, the peer-busy hold, busy delivery, the busy indication (answering a poll and polling), the keepalive rule, the UI rules (delivery, refusal, the poll's answer, every datagram sent) the frame-error rules (the error reported, also on a catch-all; a reset loss only when layer 3 was told; no rest and no reset loss after an unjustified reset), the injected payload rule and the save rules (a lost disconnect, a request released before the link is up, the disconnect answer rule, the abandon rest), which no real defect does (see its README). |

| `codegen/tests/Packet.Sdl.CodeGen.Tests/TlaEmitterTests.cs` | hand | Fails if the committed module is not exactly a fresh render of `spec/json`. TlaCheck renders afresh from JSON each run, so this test is what ties the committed module to what was checked. |

**Why the input is the JSON.** `spec/json` is exactly what the interpreter and the explorer execute, so the two checkers read the same bytes. The explorer's pre-fix fixtures (`tables-pre38`, `tables-pre40`) exist only as JSON. `--tla-tables DIR` renders any table directory.

**Why the tables are data, not operators.** The other six backends emit the tables as data for a hand-written runtime; this one does the same. Emitting each transition as a TLA+ operator was tried first. TLC's start-up level analysis (`SpecProcessor.processConstantDefns`) unfolds every operator application site separately, and with a subroutine call reachable from every action box it spent about 15 seconds per run before exploring a single state. As data, TLC starts in about a second.

**What is hand-written, and why.** The catalogues (`actions.yaml`, `predicates.yaml`, `events.yaml`) name verbs, atoms and events but do not say what they do; the only definition is the interpreter's switch. So `Ax25Meaning.tla` restates it, verb by verb and atom by atom, with the same policies (pinned semantics 1, 3 and 4 of `docs/explorer.md`), and `Ax25Runner.tla` runs the table data as the interpreter does. Nothing protocol-specific is in the generated module.

**How independent the two checkers are.** Less than "two tools" suggests, and on purpose, so that a disagreement means a bug rather than a different reading. Shared or mirrored between them:

- the input: the same JSON tables (TlaCheck renders the TLA+ from the scenario's JSON afresh for each run rather than reading the committed `spec/tla` module; the drift test is what ties the committed module to that same render);
- the meaning of every verb and atom: `Ax25Meaning.tla` is a port of `Machine.cs`, written by reading it (the split below is there so that a second meaning, written from the spec text alone, can be checked against it);
- the harness: `TwoStation.tla` is a port of `Stepper.cs`, written by reading it;
- the move set and the move order, chosen to match so both searches meet the same first violation;
- every invariant definition, including the per-step checks and their order;
- the v2.0 stub peer's rules (`V20Peer.cs`);
- the seeds;
- the quiescence definition;
- the scenarios: `Scenarios.cs` hand-copies `CalibrationTests.cs`, and the one depth-bounded row is marked by hand;
- the depth-bound handling (a TLC state constraint chosen to cut where the explorer's bound cuts).

Truly independent: the exploration engine (TLC's breadth-first search, state hashing, deadlock detection and liveness checking, against the explorer's own), and the code that runs the tables and the verbs, which is a separate implementation in a separate language though still a port of the same reading. So the cross-check finds bugs in either implementation or either search; it cannot find a shared misreading of a verb or a shared mistake in an invariant's definition.

## Selecting a meaning

The semantics are two modules with a fixed interface between them, so that the meaning of the verbs and atoms can be replaced without touching how the tables are run (ax25spec#116 Phase 2: an independent meaning, written from the spec text, checked against this one).

- `Ax25Runner.tla` declares the meaning as constant operators (`Begin`, `Arrive`, `AtomError`, `AtomValue`, `Processing`, `SignalUpper`, `SignalLower`, `InternalOut`, `Preempts`, `Preempt`, `AfterTransition`) and never names a meaning module. It owns guard selection and its order, loop regions, the subroutine binding map and the next state, and touches no meaning data.
- A meaning module `EXTENDS Ax25Values` and defines those operators plus `NewMachine` and `Persist` for the harness. `spec/tla/MeaningInterface.md` is the whole interface, worded so that a meaning can be written from it, `Ax25Values.tla`, `Ax25Runner.tla`, the tables, the catalogues and the spec text alone: the event record, the station record's fixed fields (named as the spec names them) and who reads, seeds or writes each, the harness checks that bind a meaning, the context fields the runner and the harness own, each operator's contract, the runner policies, and the reserved names.
- `docs/tla-meaning-policies.md` lists what the default meaning chose where the interface leaves the choice open, its own fields and scratch, and notes for the lockstep step. It is withheld from an independent author and is the triage checklist when two meanings disagree.
- `Ax25Semantics.tla` is the switch: `EXTENDS Ax25Meaning` followed by an unnamed `INSTANCE Ax25Runner`, which binds each constant to the meaning's operator of the same name. The harness extends it unchanged.
- `TlaCheck --meaning NAME` selects another meaning: a module in `spec/tla`, or a path to a `.tla` file. It copies the module into each model directory and rewrites that one `EXTENDS` line; the default is `Ax25Meaning`.

**The fixed fields are checked at start-up.** The harness seeds and writes some station fields with `EXCEPT`, which TLC accepts on a field the record lacks, so a meaning that named a fixed field differently would run on silently (a review found Acknowledge Pending renamed changing `busy-a-enq` from 222 to 217 states with no error). `Ax25Values.FixedFields` is the one list of those fields, and an `ASSUME` in `TwoStation.tla` stops TLC before any state is explored if `NewMachine` or `Persist` lacks one; TlaCheck reports it as the row's error. Manual check, from the repository root:

```sh
sed -e 's/MODULE Ax25Meaning /MODULE AckRenamed /' -e 's/\back\b/ackPend/g' spec/tla/Ax25Meaning.tla > /tmp/AckRenamed.tla
dotnet run --project codegen/src/Packet.Sdl.TlaCheck -- --meaning /tmp/AckRenamed.tla --only d42
# DISAGREE d42: ... TLC error: meaning interface: NewMachine lacks the fixed station field(s) {"ack"} | ...
```

Why this switch. TLC handles an `INSTANCE` with operator substitutions without any start-up cost (the level analysis that made the tables data, above, is not involved: the tables are still constants, evaluated once). It is not free while exploring: on `busy-both-trq` the safety search takes about 7% longer than with the old single module (12.8 s against 12.0 s), because every runner operator is evaluated under the substitution. A plain `EXTENDS` chain from the runner to a meaning named on its own `EXTENDS` line costs nothing, but then the runner names a meaning, the interface is a convention rather than a declaration that SANY checks for arity, and running two meanings side by side would need a generated copy of the runner per meaning. With the constants, a lockstep check of two meanings in one TLC run is two instances of the same runner: `RA == INSTANCE Ax25Runner WITH Begin <- MA!Begin, ...` and the same for `MB`, with `MA == INSTANCE Ax25Meaning` and `MB` the other meaning.

The split changes no behaviour: the operators are the old module's, moved, with two exceptions that compute the same thing. The runner stages Enquiry Response's F parameter by calling `Processing` with "F := 1" or "F := 0" instead of writing the pending F register itself, and the queue pop for `I_frame_pops_off_queue` is the meaning's `Arrive` (it ran right after the timer expiry before, and still does). Every calibration row has the same verdict and the same state count as before.

## Lockstep: two meanings side by side

`TlaCheck --lockstep --meaning M` runs a calibration row with the default meaning and `M` at once, and reports the first dispatch on which they differ. The explorer is not run.

- `LockstepSemantics.tla` stands in for `Ax25Semantics.tla` (TlaCheck writes it into the model directory under that name, its `MB` line naming `M`). It instances the runner twice, `RA` over `Ax25Meaning` and `RB` over `M`. The station record is `Ax25Meaning`'s with one more field, `lsB`, holding `M`'s record without the fixed fields other than `q` (so `M`'s queue and private fields). `Dispatch` runs every event through both; the harness sees `RA`'s result, so the default meaning drives the system and `M` shadows it.
- On each dispatch, `M`'s record is rebuilt from `lsB` with the fixed fields other than `q` taken from the default meaning's. After a dispatch that agreed they are equal anyway, so this only carries over what the harness wrote itself (the seed's `mod k n2 srej v22 rc l3 t1 t3`, the local busy condition's `own ack t1 t3`). Keeping no copy of them in `lsB` matters: the harness compares whole records (`PopChanges`, and through it the gate on T1 and T3), so a stale copy would make it see changes that are not there. With `M` an identical copy of `Ax25Meaning`, every row then has exactly the plain safety search's state count (busy-b 1069, busy-a-enq 222, cold-v22-data 210, inj-srej-tr 83).
- After each dispatch it compares an observable projection: whether the dispatch failed; and, when neither did, the effects (frames with every field, primitives to layer 3 with their labels, LM requests) in order, every fixed field except `q` (the next state included), and how the dispatch changed the length of `q` (queue entries are each meaning's own, and their labels show as soon as they are sent; the change rather than the length, because a difference set aside can leave the lengths apart). On `I_frame_pops_off_queue` it also compares whether the pop is a move for each meaning (it fails, sends a frame or changes that meaning's record), reported as `pop move`. The harness's own pop gate, `Persist(c) # m` on the combined record, is the union of the two meanings' gates; comparing them means the search follows the default meaning's gate unless the two disagree, and then the disagreement is a difference in its own right rather than something that silently steers the search (for example a pop that is a self-loop for one meaning but rotates the other's queue). Not compared: `tid`, the rows run, and fields private to a meaning. Of the compared fields, `n2`, `v22`, `srej`, `l3` and `ack` are internal state the harness never reads: a difference confined to them may never reach the air.
- A difference fails the dispatch with an error `lockstep{SIG}: ...`, where SIG is the station's state, the event and the components that differ, followed by both values. The harness reports it as a MachineError, and `Lockstep.tla` (the root module of a lockstep run) has one invariant, `LockstepAgree`, that fires on it, so TLC prints the shortest path to it. Other violations are not reported, but a state reached by one is not explored further (`CONSTRAINT LockstepGo`, plus the row's state invariants `DefinedState`, `SequenceSanity`, `AckCoherence` as constraints), so a row covers what its safety search would before it stops.
- `--lockstep-iterate N` looks past each difference: the row is run again with the SIGs found so far in the constant `LockstepKnown`; a dispatch whose SIG is in it goes on with the default meaning's result and `M`'s fixed fields (but not its queue) reset to the default's. Up to N runs per row. Later differences can be consequences of earlier ones, especially through `q`. The committed default of `LockstepKnown` is empty: nothing is excluded unless TlaCheck is iterating.
- The report lists every row's own differences in the order found, each with its counterexample, then each signature once with its shortest counterexample.
- Exit code 0 when no row differed. The workflow `.github/workflows/tla-independent.yml` (on demand, weekly, on pushes to main and on PRs that touch `spec/tla`, `codegen/src/Packet.Sdl.TlaCheck`, the `ax25spec` submodule or the workflow) runs every row with `--lockstep-iterate 8` against `Ax25MeaningIndependent`, then the plain cross-check with `--meaning Ax25MeaningIndependent`; it is informational (both steps may fail without failing the job), with the reports in the job summary and an artifact. TlaCheck deletes TLC's metadata and temporary files after every run (and a Coverage run's state dump once read), so a full run keeps only the configs and outputs.

Sanity check: `--lockstep --meaning Ax25Meaning` (the default against itself) finds no difference.

## How TLC reproduces the explorer

The harness follows `Stepper.cs` move for move: the same seeds (connected, disconnected, awaiting-v22), the same enabled moves in the same order (per station: deliver, drop, duplicate, reorder, pop, seize-confirm, flow-on/off, submit, release; then T1 at A, at B; the submit move exists only with `DataAfterConfirm`, the harness constant mirroring `ExplorerOptions.DataAfterConfirm`, where each layer 3 submits its data one frame per move once its station has emitted `DL_CONNECT_confirm` or `DL_CONNECT_indication`; the release move exists only for the stations in `ReleaseAt`, mirroring `ExplorerOptions.Release`, where layer 3 issues `DL_DISCONNECT_request` once, from Connected or TimerRecovery, once everything both sides submitted is delivered, and `Quiescent` then requires both stations Disconnected after a release; the constant `AcceptGiveUp` mirrors `ExplorerOptions.AcceptGiveUp`, the give-up rule, with the same loss count, progress, thresholds and settled state, `GiveUpSettled`; `ReleaseEarly` widens the release to `LinkStates`, the live or waiting link; `ReconnectAt` mirrors `ExplorerOptions.Reconnect`, a `Reconnect` move after the release in the move order, with `rcn` (issued once) and `pend` (waiting for `DL_CONNECT_confirm` or `DL_DISCONNECT_indication`, which `Quiescent` and `GiveUpSettled` refuse); `DataBeforeConfirm` seeds A's link-up flag true; with `DataAfterConfirm` a `DL_DISCONNECT_indication` or `_confirm` clears the link-up flag, as in the explorer; every upper-layer primitive goes through `UpperEvent`, which routes one with no arm on the page to `all_other_primitives__from_upper_layer`; `BusyAt` mirrors `ExplorerOptions.LocalBusy`, `BusyOn` and `BusyOff` moves after the reconnect, with `busy` (entered once), the action stacks in `LocalBusy` and the short-busy T1 hold `BusyHoldsT1`, which `LongBusy` lifts; `T3Moves` mirrors `ExplorerOptions.T3`, a `T3` move after the two T1 moves, the keepalive rule `KeepsAlive` in `PlainQuiescent`, the stricter `GiveUpSettled` and `t3loop`, the TimerRecovery loop entered by T3 whose give-up threshold is N2; `hb` is the peer-busy hold, raised and lowered by `HeardBusy` on every delivery and checked in `Pop`, the only move that sends I frames; `BusyIndication` is checked in `Route` next to emitter reject coherence; `UnitDataAt` and `UiForm` mirror `ExplorerOptions.UnitData` and `UiForm`, a `UnitData` move after the busy moves with `uis` (sent) and `uid` (arrived or dropped, set in `Deliver`, `Dup` and `Drop`), the per-step `UnitDataCheck` in `Inject` after the effects are routed, and `UiAccounted` in `Quiescent`; `FrameErrors` mirrors `ExplorerOptions.FrameErrors`, five `Corrupt(s, form)` moves after the reorder, with `CorruptApplies`, `CorruptInput` (the event record's `fe` field marks the corruption), the per-step `FrameErrorCheck` in `Inject` after the UI check, and the reset rule: `rs` (0, 1 honest, 2 unjustified, set in `Inject` on a dispatch from a data state that sends SABM or SABME), `told` (set in `Route`), the `Quiescent` clause that refuses rest after an unjustified reset, and `ResetLoss`; `InjectAt` and `InjectForm` mirror `ExplorerOptions.Inject` and `InjectedFrame`, an `InjectMove` after the UI datagram, gated by `InjectReady`, with `inj` (how many sent; from coverage batch 7 `InjectThen` mirrors `ExplorerOptions.InjectedThen`, a second frame, and the injected I frames carry the labels `InjLabels`, which `Route` accepts only through `acc.inj`, the payload of the I frame being dispatched when it arrives in sequence)), the same quiescent-timeout rule for T1, the same "a pop is a move only when it changes something", the same event routing and catch-alls, the same stub peer rules; and, from packet-net/ax25sdl#97's PR B, the same saves (pinned semantic 19): `FrameEvent` and `UpperEvent` hand an input the page saves to the station as itself, `InjectAs` holds it (transition `save`, appended to `sys.held[s]`) instead of dispatching it, and after every transition `Replay` consumes the held inputs the new state does not save, head first, each routed by `RouteReleased` exactly as a fresh input and dispatched through the runner's `Dispatch`, with its effects appended to the step's; `AbandonAt` mirrors `ExplorerOptions.Abandon`, an `Abandon` move after the reconnect with `ab` (issued once) and the gate `AbandonReady`; the release and the abandon pass the primitive they issued to `InjectAs`, so a DL-DISCONNECT Request routed to a catch-all is still known as one, and the `DisconnectKept` step check and `dp` (the disconnect answer rule, refused by `Quiescent`, `GiveUpSettled` and `ResetLoss`) follow the explorer's; `PlainRest` treats a path on which a station abandoned as released, with a v2.0 stub as B disconnected. Because both searches are breadth-first over the same moves in the same order, with one TLC worker they meet the same first violation: the cross-check compares not just the verdict but the length and the transition fired at every step.

Five places needed a different formulation in TLA+:

1. **Per-step invariants are a state variable.** The explorer checks reject coherence, delivery order, flow-off delivery, busy-tracks-flow and machine errors on each edge, from the step's effects. The harness computes the same checks inside the step and records the first that fires in `viol`; the invariant is `viol = NoViol`. A violating successor is always a new state (its `viol` differs), so every edge is checked, as in the explorer. Defined state, sequence sanity and acknowledgement coherence are ordinary TLC state invariants; the explorer checks them only on the station that moved, which is equivalent because the other station did not change. The step record `last` (move, station, frame, transition id) is left out of the `VIEW`, so TLC's distinct-state count is the explorer's.
2. **Deadlock** is TLC's own deadlock check. A quiescent state has a stuttering `Rest` step, so a TLC deadlock is exactly the explorer's (a terminal state that is not quiescent). It runs after the safety run, in its own TLC run, as the explorer checks deadlock only after the whole search.
3. **Liveness.** The explorer checks "from every reachable state a fault-free path reaches quiescence" on its graph (AG EF over the non-fault edges; timer-free progress also leaves out T1 edges). TLC checks LTL, so it is stated as `[]<>Quiescent` under weak fairness of the disjunction of the non-fault moves. This is sound in one direction: if the explorer's property fails, some fair behaviour circles in a region with no path to quiescence, so TLC fails too. A clean TLC verdict therefore implies the explorer's. The converse does not hold: a TLC counterexample could be a fair cycle that ignores a move which would have led out. So TLC's liveness counterexamples are compared with the explorer's verdict, not trusted alone. Two TLC costs forced this shape. Strong fairness per move (which would be tighter) is expanded by TLC into 2^n cases and did not finish on 42 states in ten minutes. And `WF_vars(A)` needs TLC's `ENABLED`, which evaluates without caching and did not finish on 3 states. So the fairness is written out: enabledness is the moves' own guards (`CanDeliver` and so on), and "a progress move was taken" is read off the step record. The argument needs every progress move to be a real (non-stuttering) step: a move that changed nothing would count as stuttering, and the fairness could be discharged falsely, so TLC could report clean where the explorer reports a violation (an independent review found this gap). The step record therefore carries a tick that flips on every move, so no move is ever a stutter.

4. **Liveness with layer 3 one-shot moves** (coverage batch 4; batch 5 adds the UI datagram, `CanUnitData`, to the one-shot moves and to the progress moves). With T3 a keepalive cycle (poll, F=1 answer, back to Connected), and with a local busy condition a poll answered by RNR, is a cycle of progress moves that the disjunctive weak fairness accepts for ever while a release, a reconnect, the end of a busy period or a submission waits; TLC then reported a lasso where the explorer's AG EF had a path out (`t3-gu-release`, `busy-both-trq`). Rows with `T3Moves`, `BusyAt` or `UnitDataAt` therefore check `QuiescenceLiveL3` / `TimerFreeLiveL3`, which add a weak fairness conjunct per one-shot move and station. The argument for soundness is the same as above: from a region with no path to quiescence, a round-robin schedule meets every conjunct without leaving it, so a clean TLC verdict still implies the explorer's. Every other row checks the formula it always did.

5. **Give-up loss and reset loss.** The explorer reports a deadlock as `GiveUpLoss` when the stuck state is a settled honest give-up that lost data (the give-up rule), and, from coverage batch 6, as `ResetLoss` when it is a settled honest frame-error reset that lost data with layer 3 told (the reset rule). TLC's deadlock check cannot say which kind of stuck state it found, so every step records it: `last.lossy` is `"yes"` or `"reset"` when the state the move leads to is such a state, and TlaCheck reads it off the last state of TLC's deadlock trace. `last` is outside the `VIEW`, so state counts are unchanged. The corrupt and inject moves are faults for the liveness formulas: neither is in `ProgressKinds`.

## Decisions beyond the explorer's pinned semantics

The explorer's register (`docs/explorer.md`, "Pinned delegated semantics") applies unchanged. These are the choices the TLA+ model had to make that the explorer does not:

- **Unmodelled write-only state.** N1 and the symbolic timer registers (SRT, T1V, T2, Next T1) are not in the TLA+ state, as they are not in the explorer's state fingerprint; their verbs change nothing. No guard reads them.
- **Maps as sets of pairs.** The receive buffer and the retained send history are sets of `<<N(s), label>>` pairs, so equal maps are equal TLA+ values whatever order built them.
- **Subroutine call depth.** The interpreter refuses a call chain deeper than 16; the TLA+ runner does not count depth. The tables have no recursive subroutine call, so the limit is never reached in either.
- **Liveness fairness**, as above: weak fairness on the disjunction of non-fault moves, stated without `ENABLED`. Sound for a clean verdict; a counterexample is compared with the explorer's.
- **Depth bound.** The one calibration row that relies on the explorer's depth bound (`d42-both-off`, the #42 runaway, marked `DepthBound` in `Scenarios.cs`) uses a TLC state constraint `TLCGet("level") <= MaxDepth`; the distinct-state counts match, which confirms the two bounds cut the graph at the same place.
- **Error text.** Interpreter error messages are reproduced closely but not byte for byte; the cross-check compares the error's kind and station, not its text.

## Calibration: explorer against TLC

Every row of the explorer's calibration suite (`CalibrationTests.cs`), plus its controls. "Agree" means: the same verdict and invariant; for a safety or deadlock counterexample, the same station, the same length and the same transition at every step; for a clean or depth-bounded run, the same number of distinct states, and for a clean run also the same set of table transitions fired across the whole search; for a liveness verdict, the same verdict (TLC's counterexample is a lasso, not the explorer's stuck state). Since coverage batch 3, a deadlock or liveness row must also have the same number of distinct states: both tools explore the whole graph before reporting those, so the count pins harness bookkeeping that changes the graph but not the verdict (the layer 3 link-up flag, see `l3-down-mod128-b3`). TLC 2.19, one worker per run.

## Wider: the explorer's grid

`--grid` runs the explorer's data-phase grid (`docs/explorer.md`, "Grid"): frames 0..3 each way, budget 0..2, k in {2, 4}, SREJ off and on, faults drop, dup and drop+dup, all invariants on: 576 cells, each compared exactly as a calibration row.

All 576 agree. Rerun on 23 October 2026 after the review fixes and the rebase onto ax25sdl#94, with `--grid --parallel 8 --workers 1 --heap 1500m`; the first pass ran out of memory in the runner after 542 cells (reading a 1.2 GB coverage dump whole, since fixed), and the other 34 were rerun with `--parallel 4 --heap 3g`. About 2.7 hours of wall time in all, most of it the coverage reruns of the largest cells. The verdicts are the explorer document's own: 460 clean, 66 deadlocks (all H1), 45 reject-coherence hits (all the #42 signature), 5 delivery duplicates (all #47 at k = 2). Every clean cell has the same number of distinct states and the same table transitions fired in both tools (the largest clean cell is 66 641 states), and every violating cell the same station, length and transition sequence. The largest cell (3+3 frames, budget 2, k = 4, drop+dup) is 602 754 distinct states; TLC takes about ten minutes per run on it with one worker, against the explorer's 20 seconds, and finds the same 26-step H1 deadlock. (A first run on 21 October, before the review fixes, also agreed on all 576.)

The grid does not change the coverage picture: it varies frame counts, faults, k and SREJ, not the inputs, so it reaches the same kinds of arm.

Not yet run: the flow-control grid (`--grid-flow`) and the v2.0 stub-peer grid.
